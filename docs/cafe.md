# Кофе / Кофейня — алдын ала тапсырыс (пилот)

Студент кампустағы кофейнядан мәзір бойынша тапсырыс береді, алу уақытын (слот) таңдайды, **қазір Kaspi арқылы**
не **алған кезде кассада** төлейді, дайын болғанда үлкен кодпен алып кетеді. Кофейня қызметкерлері тапсырыстарды
планшеттегі тақтада (`/cafe/staff`) қабылдайды. Барлығы `FEATURE_CAFE` қосқышының артында (әдепкіде өшірулі).

Код: `backend/internal/cafe` (API), `backend/internal/cafe/payments` (төлем провайдері), `services/kaspi-pos`
(Kaspi sidecar), `frontend/src/components/views/cafe.tsx`, `cafe-admin.tsx`, `frontend/src/lib/cafe.ts`,
миграция `backend/migrations/20261105000040_cafe.sql`.
Полиграфиямен ортақ бөлігі (сағаттар мен слоттар, алу коды, аудит, Telegram батырмалары, кассир сессиясы мен
әкімшінің Kaspi экрандары, бір sidecar webhook-ы) — `backend/internal/shopkit`, `frontend/src/components/views/shop-common.tsx`
([print.md](./print.md)).

## Ақша қайда түседі (өзгермейтін шешім)

- Ақша **әрқашан кофейняның өз Kaspi Pay бизнес-шотына** түседі. SIVA ақша ұстамайды, ешкімге төлемейді,
  payout жоқ.
- Кофейня өзінің Kaspi Pay қосымшасында біздің жоба нөмірін **кассир** ретінде қосады. Sidecar сол кассир
  сессиясымен QR-ды **кофейняның атынан** шығарады; біз тек төлем күйін оқимыз.
- Кассада төлеу (қолма-қол не кофейняның өз Kaspi QR-ы) — резерв жол және әр кофейняның **әдепкі** режимі
  (`payment_mode = pickup`). Kaspi — `kaspi` (тек алдын ала) не `both`.
- Kaspi QR-да комментарий өрісі жоқ: тапсырыс тек `QrOperationId` бойынша сәйкестендіріледі.

## Қалай жұмыс істейді

```text
студент ──POST /api/cafe/orders──▶ api (бағаны мәзірден өзі есептейді, слот/лимит тексереді)
        ──POST /api/cafe/orders/{id}/pay──▶ api ──X-Internal-Api-Key + кассир сессиясы──▶ kaspi-pos ──▶ Kaspi
        ◀── pay.kaspi.kz сілтемесі (телефон) / QR (компьютер)
Kaspi ◀──── студент кофейняның шотына төлейді
kaspi-pos (3 с сайын күйді сұрайды) ──webhook, HMAC──▶ api /api/cafe/kaspi/webhook ──▶ paid (бір рет)
api poller (15 с) ──────────── резерв: webhook жоғалса да pending → paid/failed; 10 мин → failed
кофейня тақтасы ◀── жаңа тапсырыс (кассада төлейтін — бірден, Kaspi — төленгенде) + Telegram «Қабылдау» батырмасы
студент ◀── «Тапсырыс қабылданды», «Дайын — алып кетіңіз» (Telegram + сайттағы хабарламалар)
```

- **Баға.** Клиент тек `itemId`, саны және опция id-лерін жібереді; сома серверде `cafe_menu_items`-тан қайта
  есептеледі, клиенттің `total`-ы еленбейді. Барлық сома — тиын (`integer`), бүтін теңге (Kaspi теңге алады).
- **Лимиттер.** Студентте алынбаған тапсырыс ≤ 2, тәулігіне ≤ 6, сағатына ≤ 10 әрекет, бір тапсырыс ≤ 30 000 ₸,
  слотқа ≤ `slot_capacity` (кофейня жолы бұғатталады — соңғы орынға екеу таласа алмайды). Тек кірген және
  келісім берген студент. Idempotency: `(user_id, idem_key)` бірегей — қайталанған сұраныс сол тапсырысты қайтарады.
- **Pay идемпотентті.** Тірі QR қайтадан қайтарылады; бір уақытта бір ғана invoice сұранысы (`pay_claimed_at`);
  төленген тапсырыс жай қайтарылады.
- **Төленді — дәл бір рет.** Webhook, poller және күй оқу бір тапсырысқа таласса да, жол `FOR UPDATE` құлпымен
  және `payment_status` тексерісімен бір рет `paid` болады; әр webhook жеткізілімі `cafe_kaspi_webhooks`-та
  `(operation_id, event)` бірегей — қайталау ештеңе өзгертпейді. Сома сәйкес келмесе — `amount_mismatch`,
  paid болмайды, менеджерге хабар.
- **Көрінуі (RLS).** Студент тек өз тапсырыстарын, қызметкер тек өз кофейнясының тапсырыстарын көреді
  (`db.WithUser` + `SET LOCAL ROLE app_user` + саясаттар). `cafe_kaspi_sessions` кестесіне `app_user`-дің қолы жоқ.
- **Аудит.** Әр өзгеріс (`created`, `pay_started`, `paid`, `accepted`, `ready`, `picked_up`, `cancelled`,
  `declined`, `no_show`, `refunded`, `refund_manual`, …) — `cafe_order_events`-те append-only жол (кім, не, қашан).
  Әкімшіде: Кофейнялар → Тапсырыстар → тапсырысты басу.
- **Болдырмау.** Студент тек кофейня қабылдамай тұрып болдырмайды. Төленген болса — кофейняның кассир сессиясымен
  Kaspi қайтару (refund) сұралады; кассир рөлі рұқсат етпесе не Kaspi бас тартса — `refund_manual`: менеджерге
  Telegram + тақтада «Ақшаны қолмен қайтару керек», менеджер Kaspi Pay-де қайтарып, «Қайтарылды» басады.
- **No-show.** Қызметкер алу уақыты + 10 мин өткен соң «Келмеді» белгілей алады. Соңғы 60 күнде 2 no-show болған
  студент енді тек **Kaspi арқылы алдын ала төлеп** тапсырыс бере алады (`pay_ahead_required`). Kaspi-мен төленген
  no-show тапсырыстың ақшасы кофейняда қалады (тағам дайындалған).
- **Хабарламалар.** `notify.Order` — транзакциялық жол: тыныш сағат пен күндік 3 хабар шегіне бағынбайды, кейінге
  қалдырылмайды (жібере алмаса, тек сайттағы хабарламада қалады). Қызметкерге — «Қабылдау» батырмасы
  (`cafe:a<id>`), басқаннан кейін «Дайын» (`cafe:r<id>`) және тақта сілтемесі.

## Sidecar: бір instance бірнеше кофейняға жете ме

`services/kaspi-pos` авторизациядан кейін **stateless**: әр сұраныс кассир сессиясын (`X-Token-SN`,
`X-Vtoken-Secret` — sidecar өз `TOKEN_SECRET_KEY`-імен шифрлаған, `X-Profile-Id`) өзімен әкеледі; ал API оларды
әр кофейняға бөлек `cafe_kaspi_sessions` жолында AES-256-GCM (`CAFE_KASPI_SESSION_KEY`) арқылы шифрлап сақтайды.
Sidecar-дың өз күйі — бір «құрылғы» (`device.json`, `keypair.json`) және бақыланатын төлемдер тізімі (әр төлем
өз сессиясын ұстайды). Сондықтан:

- **Бір sidecar instance бірнеше кофейняға жетеді** — әр кофейняның өз кассир нөмірі болса (ұсынылатын жол,
  upstream кодымен тексерілген жол). Бір контейнер, бір `kaspi-pos-data` томы.
- **Бір кассир нөмірі бірнеше бизнесте** болса: сессия біреу (нөмір бойынша), бизнесті `X-PI` (profileId)
  таңдайды. Upstream тек әдепкі бизнестің профилін алады (`OrganizationId: 0`); біз
  `POST /api/session/org-context` патчын қостық — кофейняның `kaspi_org_id`-і берілсе, логиннен кейін сол бизнестің
  profileId-і алынады. Сол нөмірмен жаңа логин бұрынғы токенді ауыстырады, сондықтан API сол нөмірлі
  (`phone_hash`) басқа кофейнялардың да токенін жаңартады, өз profileId-ін сақтап. **Тәжірибелік**: Kaspi-дің бұл
  мінезі құжатталмаған — әр кофейняда кішкентай нақты тест төлемі (мысалы, 100 ₸) өтпей тұрып `kaspi` режимін қоспаңыз.
- Бір кассир нөмірін басқа телефондағы Kaspi Pay-де қатар қолданбаңыз: «басқа құрылғыдан кіру» сессияны ығыстырады
  (Kaspi `StatusCode -101001`) → кофейня Kaspi-ден автоматты түрде уақытша шығады (төменде).

## Деплой және баптау

### Env

`docker/.env.example` — үш файлдың үлгісі (нақты мән жоқ). Кілттер: `openssl rand -hex 32`.

| Қайда | Не |
| --- | --- |
| `/opt/studenthub/.env` (api) | `FEATURE_CAFE=true`, `CAFE_KASPI_URL=http://kaspi-pos:3000`, `CAFE_KASPI_API_KEY`, `CAFE_KASPI_SESSION_KEY` (64 hex), `CAFE_KASPI_WEBHOOK_SECRET`; лимиттер (`CAFE_*`, әдепкілері файлда) |
| `/opt/studenthub/kaspi-pos.env` (sidecar, `chmod 600`) | `INTERNAL_API_KEY` (= `CAFE_KASPI_API_KEY`), `TOKEN_SECRET_KEY` (64 hex), `WEBHOOK_SECRET` (= `CAFE_KASPI_WEBHOOK_SECRET`), `MAX_PAYMENT_AMOUNT=30000` |
| `/opt/studenthub/docker/.env` (compose) | `COMPOSE_PROFILES=cafe-kaspi` — sidecar тек сонда іске қосылады; `KASPI_TAG`-ты `vps-apply.sh` жазады |

`CAFE_KASPI_SESSION_KEY` не `TOKEN_SECRET_KEY` ауысса, барлық кофейня кассирі қайта кіруі керек.

### Compose

`kaspi-pos` қызметі (`docker/docker-compose.yml`): профиль `cafe-kaspi`, жарияланған порт жоқ (тек `api`
`http://kaspi-pos:3000` арқылы жетеді; сыртқа тек Kaspi-ге https), `mem_limit: 150m`, `restart: unless-stopped`,
том `studenthub-kaspi-pos-data` (`/data`, 0700). Smart deploy `services/kaspi-pos/**` өзгерсе image-ді жинап,
тек sidecar-ды қайта қосады (`docs/deployment/smart-deploy.md`).

```bash
docker compose -f docker/docker-compose.local.yml --profile cafe-kaspi config -q   # тексеру
```

### Демо кофейня (тек dev / e2e)

```bash
cd backend && CAFE_DEMO_SEED=dev DATABASE_URL=postgres://... go run ./cmd/cafe-seed   # «Demo Coffee», is_demo
```

Демо кофейня тек `CAFE_SHOW_DEMO=true` болғанда көрінеді (production-да ешқашан қоспаңыз).

## Ертеңгі пилот: қадамдар

1. **Кофейнямен келісім** (төмендегі тізім) және кофейня Kaspi Pay-де жоба нөмірін **кассир** етіп қосады:
   Kaspi Pay қосымшасындағы қызметкерлер/кассирлер бөлімі (мәзір атауы нұсқаға қарай өзгеруі мүмкін — кофейня иесі
   көрсетеді) → жаңа қызметкер → нөмір → рөлі «Кассир». Нөмір тек осы мақсатқа: басқа телефондағы Kaspi Pay-де
   ашылмайды.
2. **Серверде env:** `/opt/studenthub/kaspi-pos.env` жасаңыз (`chmod 600`), `/opt/studenthub/.env`-ке `CAFE_KASPI_*`
   қосыңыз, `FEATURE_CAFE=true`; `/opt/studenthub/docker/.env`-ке `COMPOSE_PROFILES=cafe-kaspi`.
3. **Деплой:** `DRY_RUN=1 bash docker/smart-deploy.sh` (жоспарды көру) → `bash docker/smart-deploy.sh`
   (миграция `20261105000040_cafe.sql`, api, web, kaspi-pos). Тексеру:
   `docker compose ps` (`studenthub-kaspi-pos` healthy), `curl -s https://<сайт>/api/config | jq .features.cafe`.
4. **Әкімші → Кофейнялар → Жаңа кофейня:** атауы, ғимарат/орны, сағаттары, жұмыс күндері, слот (10 мин),
   слотқа тапсырыс (мысалы 6), `Төлем: Тек кассада` (алғашқы күні осылай бастау қауіпсіз), Kaspi Pay-дегі атауы/БСН.
   «Белсенді» — дайын болғанда ғана.
5. **Мәзір:** «Мәзір» → санаттар және позициялар (баға бүтін теңгемен; көлем/сүт опциялары JSON:
   `[{"id":"size","nameKk":"Көлемі","nameRu":"Объём","required":true,"multi":false,"choices":[{"id":"s","nameKk":"250 мл","nameRu":"250 мл","delta":0},{"id":"l","nameKk":"450 мл","nameRu":"450 мл","delta":40000}]}]`
   — `delta` тиынмен: 40000 = 400 ₸). Менеджер мәзірді кейін өзі түзете алады.
6. **Қызметкерлер:** бариста/менеджер алдымен SIVA-ға Telegram арқылы кіреді; әкімші → Пайдаланушылар-дан
   id-ін алып, кофейня карточкасында «Қызметкерлер» → id + рөл → Қосу. Планшетте `/cafe/staff` ашып,
   «Дыбысты қосу» басу (браузер дыбысқа рұқсатты тек басқаннан кейін береді).
7. **Kaspi кассир логині:** кофейня карточкасы → Kaspi → кассир нөмірі → «SMS» → кофейня қызметкері
   **кассир нөміріне** келген кодты айтады → «Растау». Күйі «қосулы · 7701***45 · <кофейня аты>» болуы керек.
   «Тексеру» — сессияны Kaspi-ден сұрайды.
8. **Сынақ тапсырыс (end-to-end):** өз аккаунтыңызбен 1 кофе: (а) кассада төлеу — тақтада пайда болуы, Қабылдау →
   Дайын → Берілді, студентке екі хабар; (б) кофейнядан `Төлем: Kaspi не касса` қойып, Kaspi-мен төлеу — телефонда
   «Kaspi қосымшасында ашу», ақша **кофейняның** Kaspi Pay тарихында көрінеді, тапсырыс «төленді» болып тақтаға
   түседі; (в) төленген тапсырысты қабылдамай тұрып болдырмау → Kaspi Pay-де қайтару пайда болды ма, әлде
   «қолмен қайтару» хабары келді ме — соны кофейнямен бірге тексеріңіз (кассир рөлінің құқығына байланысты).
9. Бәрі дұрыс болса — «Белсенді», студенттерге хабарлау.

### Қайтару (refund)

Автоматты: кофейня қабылдамай тұрып студент болдырса, не кофейня «Бас тарту» басса, не QR болдырылған тапсырысқа
кейін төленсе / екі рет төленсе. Kaspi кассирге қайтаруға рұқсат бермесе — `refund_manual`: менеджер Kaspi Pay-де
(Тарих → операция → Возврат) қайтарады да, тақтада «Қайтарылды» басады. Әкімшіде: Тапсырыстар → `refund_manual` сүзгісі.

### Sidecar сессиясы үзілсе

Белгілері: менеджерге «Kaspi байланысы үзілді» хабары, әкімшіде «сессия үзілді», мәзірде Kaspi төлем тәсілі
жоғалады (студенттер тек кассада төлей алады — `both` режимінде бәрі жұмыс істей береді). Не істеу:

1. Әкімші → кофейня → Kaspi → қайта SMS-логин (7-қадам). Бұрын жасалған QR-лар жарамсыз болуы мүмкін; poller
   оларды 10 минуттан соң `failed` етеді, студент жаңа QR алады не «Кассада төлеймін» таңдайды.
2. Логин өтпесе (`OldVersionToUpdate`) — Kaspi қосымшаның ең төменгі нұсқасын көтерген: `kaspi-pos.env`-те
   `APP_VERSION` / `APP_BUILD` (App Store-дағы Kaspi Pay iOS нұсқасы) жаңартып, `docker compose up -d kaspi-pos`.
3. Ұзаққа созылса — кофейняны `Төлем: Тек кассада` режиміне ауыстырыңыз (әкімші → Баптау). Kaspi-ден төленіп
   қойған тапсырыстар тақтада қала береді.

### Тәуекелдер

- `kaspi-pos` — **ресми емес** клиент (tapter-dev/kaspi-pos-automation, 175577e, MIT): Kaspi мобильді қосымшасының
  API-ін қайталайды. Kaspi кез келген уақытта нұсқа талабын, қолтаңбаны не ережені өзгертіп, оны тоқтатуы мүмкін;
  кассир нөмірі бұғатталуы ықтимал. Ресми Kaspi API (мысалы, Kaspi Pay үшін серіктестік) қолжетімді болса —
  тек `internal/cafe/payments`-ке жаңа `Provider` жазылады.
- Әр төлем кофейняның шотына тікелей түседі, сондықтан біздің қате ең көбі «төлем көрінбеді» болады; әрқашан
  кофейняның Kaspi Pay тарихы — шындық көзі. Күмәнді жағдайда (сома сәйкес емес, белгісіз операция) хабар келеді.
- Кассир сессиясы (екі рет шифрланған) серверде сақталады. `CAFE_KASPI_SESSION_KEY`, `TOKEN_SECRET_KEY`,
  `INTERNAL_API_KEY` ешқашан репозиторийге не чатқа түспеуі керек.
- `/api/cafe/kaspi/webhook` сыртқы nginx арқылы да ашық, бірақ тек HMAC қолтаңбасы дұрыс сұранысты қабылдайды.

### Кофейнямен келісім (қысқа тізім)

      (бар болса — бөлек шарт).
- [ ] Кофейня жоба нөмірін **кассир** рөлімен қосады және кез келген уақытта өзі өшіре алады.
- [ ] Қайтаруды кім және қанша мерзімде жасайды (автоматты өтпесе — менеджер, мысалы 24 сағат ішінде).
- [ ] No-show ережесі (Kaspi-мен төленген, бірақ алынбаған тапсырыс — ақша кофейняда, тағам дайындалған).
- [ ] Мәзір мен бағаның дұрыстығына кофейня жауапты; «таусылды» белгісін бариста өзі қояды.
- [ ] Жұмыс уақыты, слоттың сыйымдылығы, тапсырыс қабылдамайтын күндер.
- [ ] Байланыс: кофейня менеджері ↔ SIVA әкімшісі (Telegram), ақау болғанда «тек кассада» режиміне көшу.
- [ ] Дербес деректер: кофейня тек студенттің қысқа атын («Аружан С.») және тапсырысты көреді; телефон нөмірі берілмейді.
- [ ] Пилот мерзімі және тоқтату тәртібі (`FEATURE_CAFE=false` не кофейня «Белсенді» емес).

## API

Толық маршруттар мен рұқсаттар: [SECURITY.md](./SECURITY.md) (`cafe` бағаны). Қысқаша:

| Кім | Маршрут |
| --- | --- |
| Барлығы | `GET /api/cafes`, `GET /api/cafes/{id}/menu` (мәзір + бүгінгі слоттар) |
| Студент | `POST /api/cafe/orders`, `GET /api/cafe/orders/mine`, `GET /api/cafe/orders/{id}`, `POST …/{id}/cancel`, `POST …/{id}/pay` (`{"method":"pickup"}` — кассаға ауысу) |
| Қызметкер | `GET /api/cafe/staff/orders?cafe=&status=`, `POST /api/cafe/staff/orders/{id}/accept\|ready\|picked-up\|no-show\|decline\|refunded`, `GET /api/cafe/staff/menu`, мәзір CRUD (менеджер), `POST …/menu/items/{id}/availability` |
| Әкімші | `GET/POST /api/admin/cafes`, `PUT /api/admin/cafes/{id}`, қызметкерлер, `GET /api/admin/cafe/orders[/{id}]`, Kaspi логин (`…/kaspi/login/start`, `…/verify`, `…/check`, `DELETE …/kaspi`) |
| kaspi-pos | `POST /api/cafe/kaspi/webhook` (`X-Webhook-Signature: sha256=<HMAC>`) |

## Тесттер

- Go: `internal/cafe` (бағаны тек мәзір анықтайды, белсенді тапсырыс шегі параллель сұраныстарда да, idempotent
  create/pay, webhook + poller + оқу жарысында paid бір рет, қызметкер басқа кофейняны көрмейді, студент бөтен
  тапсырысты көрмейді — RLS деңгейінде де, болдырмау ережелері мен refund/manual refund, no-show → алдын ала төлем,
  poller timeout), `internal/cafe/payments` (sidecar келісімі, қате түрлері, шифрлау), `internal/notify`
  (`Order` шек пен тыныш сағатқа бағынбайды), `internal/bot` (батырмалар).
- Sidecar: `cd services/kaspi-pos && npm test`.
- Браузер: `frontend/e2e/cafe.spec.ts` (mock API: кассада төлеу, Kaspi жолы, тақта), real API:
  `frontend/e2e/real-api/cafe.spec.ts` (жалған kaspi-pos `e2e/real-api/fake-kaspi.ts`).
