# Полиграфия — файл жүктеп, кезекке тұру (пилот)

Кампустағы полиграфияда кезек көп: студенттер файлды операторға WhatsApp-пен жібереді, ол бір-бірлеп басады. Енді
студент Student Hub-та файлдарын жүктейді, әр файлды баптайды (дана, түсі, екі жақты, беттер аралығы, қағаз өлшемі,
түптеу, ламинация), **сервер есептеген бағаны** көреді, тауар қосады (папка, қалам…), алу уақытын не «мүмкіндігінше
тез» таңдайды, **Kaspi арқылы** (полиграфияның өз шотына) не **кассада** төлейді, кезектегі орнын көреді, дайын
болғанда хабар алады. Оператор планшеттегі тақтада (`/print/staff`) кезекпен жұмыс істейді. Барлығы `FEATURE_PRINT`
қосқышының артында (әдепкіде өшірулі).

Код: `backend/internal/printshop` (API), `backend/internal/shopkit` (кофейнямен ортақ қабат),
`frontend/src/components/views/print.tsx`, `print-admin.tsx`, `shop-common.tsx`, `frontend/src/lib/print.ts`,
миграциялар `backend/migrations/20261105120060_print.sql`, `20261106000100_pickup_counter.sql`.

## Өзгермейтін шешімдер

- **Ақша** әрқашан полиграфияның өз Kaspi Pay шотына түседі (кофейнядағыдай, [cafe.md](./cafe.md)). Kaspi QR
  полиграфияның **өз кассир сессиясымен** (`print_kaspi_sessions`) шығарылады; Student Hub ақша ұстамайды.
  Кассада төлеу — резерв жол және әдепкі режим (`payment_mode = pickup`).
- **Баға тек серверде.** Клиент файл id-ін, опцияларды және тауар id/санын жібереді; сома `print_services` пен
  `print_goods`-тан қайта есептеледі (`internal/printshop/pricing.go`). `POST /api/print/quote` — тек алдын ала
  көрсету; `POST /api/print/jobs` бәрін басынан қайта есептейді, клиенттің `total`-ы еленбейді.
- **Файлдар жабық.** Ешқашан public емес, тек 5 минуттық қол қойылған сілтемемен, сақтау мерзімінен соң өшіріледі.

### Бет санын қалай білеміз (таңдалған жол)

| Формат | Бет саны | Баға |
| --- | --- | --- |
| PDF | серверде есептеледі: таза Go парсер (`github.com/ledongthuc/pdf`, каталог → `/Pages` → `/Count`), 5 с шегі, panic ұсталады | бірден түпкілікті (`final`) |
| JPG / PNG | 1 бет | түпкілікті |
| DOCX / XLSX / PPTX | **студент жазады** (DOCX/PPTX-тің өз `docProps/app.xml` дерегі — `<Pages>`/`<Slides>` — тек алдын ала толтырады) | `review`: оператор файлды ашып, **растайды** не **өзгертеді** |
| Сервер оқи алмаған PDF (құпиясөзді, бұзылған) | студент жазады | `review` |

Неге сервер конвертерсіз: API контейнерінің жады шегі 150 МБ (ортақ VPS), LibreOffice бір конвертацияға жүздеген МБ
алады және оны оқшаулау (seccomp, желісіз, уақыт шегі) бөлек сервис талап етеді. Пилотқа «студент жазады → оператор
растайды → өзгерсе студент келіседі» жолы қауіпсіз әрі арзан. Кейін қажет болса, бөлек оқшауланған конвертер
контейнері тек `Inspect`-ке бет санын береді — қалғаны өзгермейді.

Баға күйі (`print_jobs.price_state`):

- `final` — келісілген баға. Тек осы күйде Kaspi төлемі және басып шығару ашылады.
- `review` — бет санын студент жазды. Тақтада «Бағаны растау» (сол сома → `final`, студентке сұрақ жоқ) не
  «Бағаны өзгерту» (жаңа сома + себеп).
- `proposed` — оператор жаңа соманы ұсынды (`proposed_total`, `adjust_reason`). Студентке хабар келеді; ол
  **келіседі** (→ `final`, жаңа сома) не **бас тартады** (тапсырыс болдырылмайды). Төленген тапсырыстың бағасы
  өзгертілмейді — айырманы кассада шешеді.

## Қалай жұмыс істейді

```text
студент ──POST /api/print/uploads (multipart)──▶ api: магия-байт, 20 МБ, тәуліктік квота, бет саны, кездейсоқ ат
        ──POST /api/print/quote──▶ сервер бағасы (сақталмайды)
        ──POST /api/print/jobs──▶ қайта есептеу, файлдар тапсырысқа байланады, кезек (queued_at)
        ──POST /api/print/jobs/{id}/pay──▶ api ──кассир сессиясы──▶ kaspi-pos ──▶ Kaspi (полиграфияның шоты)
kaspi-pos ──webhook──▶ /api/cafe/kaspi/webhook ──(shopkit.RegisterOperations)──▶ print: paid (бір рет)
оператор тақтасы ◀── кезек ретімен: файлды қол қойылған сілтемемен жүктейді → «Басып жатырмын» → «Дайын» → «Берілді»
студент ◀── «Дайын — алып кетіңіз» (Telegram + сайттағы хабар), «Жаңа баға: … — растаңыз»
```

- **Күйлер:** Жаңа (`new`) → Басып жатыр (`printing`) → Дайын (`ready`) → Алынды (`picked_up`); сондай-ақ
  `cancelled`, `no_show`. Кезектегі орын — сол полиграфиядағы ертерек кезекке тұрған ашық тапсырыстар саны.
- **Kaspi тапсырысы** кезекке **төленгенде** тұрады (`queued_at` = төлем уақыты); баға `review`/`proposed` болса,
  оператор оны тақтада бірден көреді (бағаны тексеру үшін), бірақ басуға рұқсат жоқ.
- **Болдырмау:** студент тек басып шығару басталмай тұрып. Төленген болса — полиграфияның сессиясымен Kaspi қайтару,
  болмаса `refund_manual` (менеджерге хабар, тақтада «Қайтарылды»). Оператор да «Бас тарту» жасай алады.
- **No-show:** «Дайын» болғаннан (не алу уақытынан) кейін `PRINT_NO_SHOW_GRACE_MIN` (120 мин) өткен соң.
- **Аудит:** әр өзгеріс `print_job_events`-те append-only (`created`, `price_confirmed`, `price_proposed`,
  `price_approved`, `price_rejected`, `pay_started`, `paid`, `printing`, `ready`, `picked_up`, `declined`,
  `refunded`, `refund_manual`, `files_deleted`, …). Әкімші → Полиграфиялар → Тапсырыстар → тапсырысты басу.
- **Хабарламалар:** `notify.OrderIn(CatPrint)` — транзакциялық (тыныш сағат пен күндік шекке бағынбайды). Хабарға
  файл аты да, мазмұны да кірмейді — тек код, файл саны, баға. Операторға «Басып жатырмын» батырмасы (`print:p<id>`),
  кейін «Дайын» (`print:r<id>`).

## Беру және басу реті (кішкентай бөлме, күніне жүздеген тапсырыс)

Зерттеу: [research/print-competitors.md](./research/print-competitors.md).

- **Алу коды бірегей.** Полиграфияда — 4 сан (1000–9999), кофейняда — 3 сан. `shopkit.UniqueCode` код таңдағанда
  дүкеннің ашық тапсырыстарының кодтарын ешқашан қайталамайды, бүгін жабылғандарының кодын да мүмкіндігінше
  қайталамайды (студент бүгінгі хабарды әлі оқуы мүмкін). Дүкен жолы `FOR UPDATE` құлпында; дерекқордағы
  `print_jobs_open_code` / `cafe_orders_open_code` (ашық тапсырыстар арасында бірегей) — екінші қорған.
  Неге 4 сан: 3 сан — 900 код, ал күніне ~1000 тапсырыс болса бүгінгі кодтарды қайталамау мүмкін емес.
- **QR.** Студенттің тапсырыс бетінде (тапсырыс ашық тұрғанда) QR бар: `PJ-<id>-<код>-<HMAC>` (кілт
  `SESSION_SECRET`-тен, «print-pickup-token-v1»). Онда аты жоқ; тапсырыс жабылған соң көрсетілмейді.
- **Іздеу.** Тақтаның жоғарғы жағында үлкен өріс: оператор студент айтқан кодты жазады не QR сканерлейді
  (камера — `BarcodeDetector` бар браузерде; USB сканер сол өріске жазады) → `GET /api/print/staff/lookup?shop=&q=`
  → тапсырыс, студенттің **аты** («Аружан С.» — «атыңыз?» деп сұрау үшін), бет саны, бірінші файл, кассада
  төлейтін сома → «Берілді». Бүгін берілген тапсырыс та табылады («бұрын берілген»).
- **«Берілді» сәйкестікті талап етеді:** `POST …/picked-up` денесінде `{"code":"4821"}` не `{"token":"PJ-…"}`;
  басқа тапсырыстың коды/QR-ы — `409 code_mismatch`. Telegram батырмаларында беру жоқ.
- **Басу реті = стек реті.** Тақтадағы рет — `queued_at`, ескісі бірінші. Оператор жаңа тапсырыстарды белгілейді
  → «Басу реті»: тізім кезек ретімен (қалай белгіленгеніне қарамай), әр тапсырыс — өз PDF-і, бөлек басып шығару
  тапсырмасы. Сосын «Барлығы: басып жатырмын / дайын» (`POST /api/print/staff/jobs/bulk`, ≤ 40, кезек ретімен,
  әрқайсысы өз транзакциясында; беру ешқашан топтамамен емес).
- **Басуға дайын PDF** оператордың **өз браузерінде** жиналады (`pdf-lib`, тек батырма басылғанда жүктеледі):
  API контейнерінде 150 МБ шек бар және конвертер жоқ. Студенттің беттері өзгертілмейді (мөр, масштаб жоқ);
  беттер аралығы мен даналар қолданылады; екі жақты дананың беті тақ болса, артына бос бет қосылады (келесі дана
  жаңа параққа түседі). Қағаз/түс/екі жақтылығы әртүрлі файлдар бөлек PDF болады (басу терезесіндегі баптау
  бөлек). Office файлдарын браузер біріктіре алмайды — тізімде «өз бағдарламасынан басыңыз» деп тұрады;
  ашылмаған PDF (құпиясөзді, бұзылған) — түпнұсқасын жүктеп басу.
- **Стектерді бөлу (`print_shops.separator`):**
  - `none` (әдепкі) — қағазсыз: принтер драйверінде **«Offset / Сдвиг / Job separation»** қосулы болса (Konica
    Minolta және көп офис МФУ), әр басып шығару тапсырмасы науада сәл ығысып шығады. Тақтада бір рет кеңес
    көрсетіледі.
  - `slip` — кесетін парақшалар: бір A4-те 4 тапсырыс (A6), топтамаға бір PDF; қағаз шығыны ÷4.
  - `full` — әр тапсырыс алдында толық парақ (полиграфия өзі таңдаса). Парақша/парақта: код, аты, файлдар,
    бет×дана, түптеу, ескертпе, төлем; жоғарыда қалың сызық (стектен оңай көрінеді).
  Студенттің құжатына ешқашан ештеңе басылмайды.
- **«Дайын» бағаны** кезек ретімен не код бойынша сұрыпталады (науадағы стекті кодпен реттеп ұстау үшін).
  Әр бағанда ≤ 150 тапсырыс көрсетіледі (`counts` — нақты саны); қалғаны кодпен ізделеді.

## Зерттеуден қосылғандар

- **Файлсыз бағаны есептеу** (`POST /api/print/estimate`, кіру керек емес, IP бойынша шек): студент бет санын,
  данасын, өлшемін, түсін, екі жақтылығын, түптеуін таңдайды — сома `Quote`-тың өз ережелерімен серверде
  есептеледі, ештеңе сақталмайды. Нақты баға — файл жүктелген соң.
- **Беттерді алдын ала көру:** студент таңдаған PDF-тің (аралықтағы ≤ 8 бет) кішкентай суреттері студенттің өз
  құрылғысында `pdf.js`-пен салынады («Беттерді көру» басылғанда ғана жүктеледі, бөлек worker файлы жоқ); көлденең
  беттер белгіленеді. Серверге ештеңе жіберілмейді, API ештеңе рендерлемейді.
- **Шамамен дайын болу уақыты:** тапсырыс бетінде «≈ 15 минутта дайын» — алдыңғы тапсырыстардың басылатын беттері
  × `PRINT_SECONDS_PER_PAGE` (4 с) + тапсырыс саны × `PRINT_SECONDS_PER_JOB` (60 с), 5 минутқа дейін дөңгелектеледі;
  полиграфия жабық болса көрсетілмейді.
- **Бір еске салу:** «Дайын» тапсырыс no-show шегінің жартысында (`PRINT_NO_SHOW_GRACE_MIN`/2, дайын болған не алу
  уақытынан) алынбаса, студентке бір рет хабар (`reminded` оқиғасы — қайталанбайды). Poller жібереді.
- **Соңғы баптаулар:** студенттің осы полиграфиядағы соңғы тапсырысының өлшемі, түсі, екі жақтылығы, данасы,
  түптеуі (тек осы құрылғыда, `localStorage`) жаңа файлға қойылады; беттер аралығы мен файл ешқашан есте
  сақталмайды; полиграфия бағаламайтын опция түсіп қалады.
- **Күндік есеп** (тақта → «Есеп», `GET /api/print/staff/report?shop=&day=`): келді, берілді, алынбады,
  болдырылмады, ашық; сома Kaspi / касса бойынша (берілген тапсырыстар), қайтарылғаны; ақ-қара және түсті беттер,
  парақ; кезектен дайынға дейінгі медиана.

Қабылданбағандар (себебімен — [research/print-competitors.md](./research/print-competitors.md) §6): Telegram бот
арқылы файл жүктеу (бот модулі ортақ, Bot API файл шегі 20 МБ — бөлек тапсырма); беттер бойынша түс таңдау
(бағасы мен оператор жұмысы күрделенеді, бәсекелестерде жоқ; ескертпе өрісі жеткілікті); қайта тапсырыс (файлдар
3 күнде өшеді — «соңғы баптаулар» оның арзан түрі); баға қою/рейтинг (бір оператор — жеке қысым, дәлел әлсіз);
серверде Office конвертациясы (150 МБ шек); принтерде «hold-and-release» (кассадағы оператор моделіне келмейді).

## Прайс (менеджер не әкімші толтырады)

Барлық сома — тиын, бүтін теңге (2000 = 20 ₸). Қызмет түрлері (`print_services.kind`, `pricing` JSON сервер
тексереді — `ValidPricing`):

| Түрі | Мысал `pricing` | Есеп |
| --- | --- | --- |
| `print` — басып шығару, көшірме файлдан, плакат (A2–A0) | `{"sizes":{"A4":{"bw":2000,"color":10000,"bwDuplex":1500,"colorDuplex":9000},"A3":{"bw":4000,"color":20000,"bwDuplex":0,"colorDuplex":0}}}` | бет × бір жақ бағасы × дана; `color`=0 — түсті жоқ, `…Duplex`=0 — екі жақты жоқ |
| `binding` — түптеу (пружина, термо) | `{"tiers":[{"maxSheets":50,"price":50000},{"maxSheets":150,"price":80000}]}` | бір данаға, парақ санына қарай (екі жақты — бет/2) |
| `lamination` | `{"sheet":{"A4":15000,"A3":25000}}` | парақ × дана |
| `unit` — көшіру (қағаздан), сканерлеу, визитка, басқа | `{"price":5000,"unitKk":"бет","unitRu":"стр."}` | бірлік × саны |

`online = false` — қызмет прайста көрінеді («кассада» белгісімен), бірақ онлайн тапсырысқа қосылмайды (мысалы, бет
санын тек көзбен санайтын көшіру). Тауарлар (`print_goods`) — баға және «бар/жоқ» (оператор тақтада ауыстырады).
Ең аз тапсырыс (`min_order`) — сома одан аз болса, айырма бөлек жолмен қосылады.

## Файлдар және қауіпсіздік

- **Тексеру ретімен:** өлшем (≤ 20 МБ, дене сол жерде кесіледі; nginx `client_max_body_size 21m` тек
  `/api/print/uploads`-та) → байттар (PDF `%PDF-`, JPEG, PNG, ZIP ішінде нақты `word/`/`xl/`/`ppt/` және
  `[Content_Types].xml`; **макросы бар** (`vbaProject.bin`, `macroEnabled`) және ескі `.doc`/`.xls` қабылданбайды;
  файл атауы мен Content-Type еленбейді) → тәуліктік квота (`PRINT_DAILY_FILES` 30 файл, `PRINT_DAILY_MB` 200 МБ,
  advisory lock — жарыс жоқ) → бет саны. Бір тапсырысқа ≤ 5 файл, бір файл бір тапсырысқа ғана.
- **Сақтау:** `UPLOAD_DIR/print/<32 hex>.<ext>`, `0640`, атомарлы жазу. Студенттің файл аты тек көрсетуге
  (тазаланған `display_name`). Сурет қайта кодталмайды (басу сапасы үшін) — EXIF сақталады, бірақ файл жабық және
  мерзімі өткенде өшіріледі.
- **Жүктеу (download):** `GET /api/print/files/{id}?v=<viewer>&e=<unix>&s=<HMAC>` — кілт `SESSION_SECRET`-тен
  туындайды, қолтаңба файлды, қарау құқығы бар адамды және мерзімді (5 мин) байлайды; беру сәтінде `viewer` әлі де
  файлдың студенті не тапсырыс полиграфиясының қызметкері екені қайта тексеріледі. Жауап: `Content-Disposition:
  attachment`, тұрақты `Content-Type`, `nosniff`, `CSP: default-src 'none'; sandbox`, `Cache-Control: private,
  no-store`, `Referrer-Policy: no-referrer`. Сессиясыз жұмыс істейді (Telegram Mini App сыртқы браузерде ашқанда да),
  сондықтан сілтемені бөтенге жібермеу керек — ол 5 минуттан соң жарамсыз.
- **RLS:** студент өз файлдары мен тапсырыстарын, қызметкер тек өз полиграфиясының тапсырыстары мен файлдарын
  көреді (`db.WithUser`); `print_kaspi_sessions`-ке `app_user`-дің қолы жоқ. Бөтен полиграфияның тапсырысы «жоқ»
  (404) болып көрінеді.
- **Лимиттер:** жүктеу 40/сағ, тапсырыс жасау 20/сағ, белсенді тапсырыс ≤ 3, тәулігіне ≤ 10, бір тапсырыс ≤ 30 000 ₸
  (`PRINT_MAX_ORDER_TOTAL`, sidecar-дың `MAX_PAYMENT_AMOUNT`-ынан аспасын), квота 300/сағ.
- **Логтар:** файл мазмұны да, аты да логқа жазылмайды (тек id).
- **Антивирус жоқ — тәуекел.** Сервер файлды ешқашан орындамайды және тек бет санын оқиды, бірақ зиянды PDF/DOCX
  оператордың компьютерінде ашылғанда қауіпті болуы мүмкін. Сондықтан: макросы бар құжаттарды қабылдамаймыз;
  оператор файлдарды **жаңартылған** PDF-көрсеткіш/Office-пен, Windows Defender (не басқа антивирус) қосулы,
  әкімші емес аккаунтта ашады; Office-те «Қорғалған көрініс» өшірілмейді; күдікті файлды «Бас тарту» етеді. Болашақта
  ClamAV-ты бөлек контейнерде (жады шегі сақталса) `Inspect`-ке қосуға болады.

### Сақтау мерзімі (retention)

- Жабылған тапсырыстың (`picked_up`, `no_show`) файлдары **`retention_days`** (әдепкі 3, 1–30) күннен соң өшіріледі;
  болдырылған тапсырыстың файлдары — 10 минуттан соң; тапсырысқа қосылмаған жүктеме — 24 сағаттан соң.
- Өшіргенде байттар дискіден кетеді, `print_files` жолы қалады (`deleted_at`, аты, өлшемі — аудит үшін),
  тапсырыста `files_deleted_at` және `files_deleted` оқиғасы.
- Poller (`PRINT_POLL_SECONDS`, 15 с) Kaspi күйлерін тексереді, ал retention-ді 10 минутта бір рет жүргізеді
  (`FEATURE_PRINT` қосулы болса ғана). Аккаунт өшірілсе, студенттің барлық файлы бірден өшеді (тапсырыстар
  полиграфияда анонимді қалады).
- Резерв көшірме (`pg_dump`) файлдарды қамтымайды; `/opt/studenthub/uploads/print` бэкапқа қоспаңыз.

## Kaspi: кофейнямен ортақ

`services/kaspi-pos` sidecar біреу; оның `WEBHOOK_URL`-ы біреу (`/api/cafe/kaspi/webhook`). Кофейня өзі білмейтін
операцияны тіркелген басқа дүкендерден сұрайды (`shopkit.RegisterOperations`), сондықтан полиграфия төлемі де сол
webhook арқылы бір рет `paid` болады (`cafe_kaspi_webhooks.outcome = print:paid`). Кассир логині, тексеру, ажырату —
кофейнядағы экрандардың өзі (`shopkit.KaspiAdmin`), тек бөлек кесте `print_kaspi_sessions`. Бір кассир нөмірін
кофейня мен полиграфия бөліспеуі керек (әр бизнестің өз нөмірі).

## Деплой және баптау

1. `/opt/studenthub/.env`: `FEATURE_PRINT=true` (Kaspi керек болса — кофейнядағы `CAFE_KASPI_*` және
   `COMPOSE_PROFILES=cafe-kaspi` бұрыннан бар болуы керек). Лимиттер — `docker/.env.example`.
2. Хосттағы nginx: `docker/nginx.host.conf`-тағы `location = /api/print/uploads` (21m) блогын көшіріп,
   `nginx -t && systemctl reload nginx`.
3. `DRY_RUN=1 bash docker/smart-deploy.sh` → `bash docker/smart-deploy.sh` (миграция `20261105120060_print.sql`,
   api, web). Тексеру: `curl -s https://<сайт>/api/config | jq .features.print`.

## Пилот: қадамдар

1. **Полиграфиямен келісім** (төмендегі сұрақтар).
2. **Әкімші → Полиграфиялар → Жаңа полиграфия:** атауы, ғимарат/кабинет, сағаттары, күндері, қабылдайтын
   форматтар, ең аз сома, файлды сақтау күні, `Төлем: Тек кассада` (алғашқы күні), ескертпе студенттерге.
   «Белсенді» — дайын болғанда.
3. **Прайс:** «Прайс» → қызметтер (жоғарыдағы JSON үлгілері, форма әр түрге үлгіні өзі қояды) және тауарлар.
4. **Қызметкерлер:** оператор/менеджер алдымен Student Hub-қа кіреді; әкімші → Пайдаланушылар → id → карточкада
   «Қызметкерлер» → рөл (`оператор` / `менеджер`). Планшетте `/print/staff`, «Дыбысты қосу».
5. **Kaspi (міндетті емес):** полиграфия Kaspi Pay-де жоба нөмірін **кассир** етіп қосады → карточка → Kaspi →
   нөмір → SMS → «Растау». Сосын `Төлем: Kaspi не касса`. 100 ₸ сынақ төлемін полиграфиямен бірге тексеріңіз.
6. **Сынақ (end-to-end):** (а) 3 беттік PDF, екі жақты, кассада → тақтада көрінеді, файл жүктеледі, «Басып
   жатырмын» → «Дайын» → студентке хабар → «Берілді»; (б) DOCX: бет санын жазу → тақтада «Бағаны өзгерту» →
   студент келіседі → Kaspi → ақша **полиграфияның** Kaspi Pay тарихында; (в) 3 күннен соң файлдың өшкенін
   тексеру (`/opt/studenthub/uploads/print`).
7. Бәрі дұрыс болса — «Белсенді», студенттерге хабарлау.

### Полиграфиядан сұрайтын сұрақтар

- [ ] **Толық прайс:** А4/А3 ақ-қара және түрлі түсті (бір жақ / екі жақ), А5, плакат (A2–A0), көшіру (қағаздан),
      сканерлеу, түптеу түрлері мен парақ шектері, ламинация, визитка, фото, басқа қызметтер; тауарлар (папка,
      файл-қалта, қалам, дәптер…) және бағасы; ең аз тапсырыс сомасы.
- [ ] **Форматтар:** қандай файлдарды басады (PDF, DOCX, XLSX, PPTX, JPG/PNG)? Ескі `.doc`, Google Docs сілтемесі,
      `.cdr`/`.psd` керек пе (қазір жоқ)? Түрлі түсті тек белгілі өлшемде ме?
- [ ] **Kaspi:** Kaspi Pay бизнес-шоты бар ма; жоба нөмірін **кассир** етіп қоса ала ма; кассир қайтару (refund)
      жасай ала ма; сатуды кім қайтарады (автоматты өтпесе).
- [ ] **Жұмыс уақыты, үзіліс, демалыс күндері;** бір сағатта шамамен қанша тапсырыс басады; «мүмкіндігінше тез»
      орташа қанша уақыт.
- [ ] **Файлдар:** файлды қанша күн сақтау керек (әдепкі 3 күн); оператор файлды қандай компьютерде, қандай
      бағдарламамен ашады; антивирус бар ма (жоғарыдағы тәуекел).
- [ ] **No-show:** дайын тапсырысты қанша күн сақтайды; кассада төлемейтін, келмеген студент — не істейді.
- [ ] **Оператор(лар):** кім, Telegram-ы бар ма, планшет/компьютер бар ма; менеджер (прайсты өзгертетін) кім.
- [ ] **Дербес деректер:** оператор тек қысқа атты («Аружан С.») және файлдарды көреді; файл мерзімі өткенде
      өшіріледі; файлды басқа мақсатқа пайдаланбайды, үшінші тұлғаға бермейді.
- [ ] Пилот мерзімі, байланыс (полиграфия менеджері ↔ Student Hub әкімшісі), тоқтату тәртібі (`FEATURE_PRINT=false`
      не «Белсенді» емес).
