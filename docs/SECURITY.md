# Server security audit

Generated by `go run ./cmd/routes > docs/SECURITY.md`. The inventory walks the exact
runtime registrations, including the fallback; tests reject undocumented routes, obsolete
entries, and document drift. GET also accepts HEAD through Go's ServeMux.

“signed-in” means student, ambassador, university_staff, employer or admin. Membership,
consent, age, ownership and university restrictions still apply. “employer” means an
employer_members relationship, not merely the users.role value. A “no” in validation on a
read/action with no parameters means there is no application input to validate; authentication
is listed separately. Rate limits are shared Postgres counters, with an in-memory fallback
when Postgres is unavailable. All browser writes use auth.Write (allowed Origin/Referer,
per-IP and per-user budget); /api/client-errors also has a fixed 5/IP/minute budget.

The only write-guard exception is POST /api/telegram: Telegram's constant-time webhook
secret check replaces browser origin/rate checks. All six GET cron endpoints mutate data,
but accept only a nonempty CRON_SECRET bearer token and record successful completion.
Tests reject missing/wrong secrets and ensure failed attempts do not advance cron state.

Findings fixed: analytics ingestion lacked the shared origin guard; chat used a separate
write policy. Both now pass through auth.Write. Account deletion used to swallow disk
removal errors; it now refuses to report success while a photo cannot be deleted.
The new settings, error and cron tables have RLS enabled and no app_user privileges.
Error storage uses constant diagnostics/categories, static screen names and browser major
versions: arbitrary names, IDs, tokens, full URLs, IPs and free-form details are not persisted.

Scope: Go API only. Existing feature tests cover student/company/university isolation;
the launch tests add router-wide write/role/switch checks, populated catalog-driven account
deletion, settings and monitoring integration tests. Frontend XSS/CSP, browser scenarios,
PWA and repository-history secret scanning are outside this server-only assignment.
Session signing/cookie settings and Telegram/cron secret checks remain covered by auth/bot tests.
Local market files are removed before the SQL commit: retries are idempotent, but a later
transaction failure can leave a surviving database row without its already-removed photo.
The API assumes the trusted reverse proxy overwrites client IP forwarding headers.
Quiz live games use the only WebSocket route, GET /api/quiz/live/ws: Vercel rewrites do not
proxy WebSockets, so browsers connect to the API origin directly, where the site's cookies do
not exist. The socket therefore accepts no cookie at all: it requires a signed 2-minute join
token (HMAC with a key derived from SESSION_SECRET, separate from session cookies) issued by
POST /api/quiz/live/join or /sessions over normal HTTPS, and an Origin in ALLOWED_HOSTS.
Unlisted quizzes are readable by their 10-character share code (about 57 bits); answer keys
are never part of a play view and live in a separate owner-only RLS table.
