# TAPSYRMA 04: Student Hub — аккаунттар, ортақ дерекқор, рөлдер және хабарлама бюджеті (іргетас)

Бұл — бар жобаның жалғасы. 01–03 промпттар орындалған: AI-чат қауіпсіз, hash-роутинг пен бөлісу бар, контент `/api/content` арқылы (Google Sheets + `data/*.json`), аналитика бар, мерзімді еске салатын бот `/api/telegram` webhook арқылы жұмыс істейді және Supabase-тегі `reminders` кестесін қолданады. Алдымен бүкіл репозиторийді зерттеп шық.

Код құрылымы (сақта, қайта жазба): `index.html` — бір файлдық қолданба: `VIEWS` тізілімі (әр экран — функция), `ACT` (`data-act` батырмалары), `ON` (`data-on` өрістері), `S` күйі (`localStorage`), `tt(kk, ru)` аудармалары, `esc()` экрандау, `HASH_OF`/`NAME_OF` роутингі, `notifs()` хабарламалары. `api/*.js` — Vercel серверлік функциялары (ESM, `export default async function handler(req, res)`), `api/chat.js` — үлгі стиль.

Неге керек: 05–10 промпттардағы функцияларға (іс-шаралар мен QR, амбассадор кабинеті, менторлар, отдам даром, жария портфолио, университет пен жұмыс беруші кабинеттері) ортақ дерекқор, аккаунт пен рөлдер керек. Қазір профиль тек құрылғыда.

Жобаның өз ережелері (`replica/fixes.md`): жүйеден ешқашан шығармау, жарнама мен артық лента жоқ, хабарламаларды санат бойынша өшіруге болады, «артқа» қосымшадан ешқашан шығармайды.

МАҢЫЗДЫ: кезең-кезеңмен жаса, әр кезеңнен кейін тоқтап, маған тексеруге бер. Аккаунтсыз студент сайтты бұрынғыдай толық қолдана алуы керек.

## 1-КЕЗЕҢ — API құрылымы және барлық кейінгі промпттарға ортақ ережелер
- Дерекқор: 03-промпттағы Supabase жобасы. Барлық схема — миграция файлдары (`supabase/migrations/`). Тегін деңгейдің қазіргі шектеулерін (дерекқор, файл қоймасы, белсенді емес жобаны тоқтату, резервтік көшірме) ресми сайттан тексеріп, README-ге жаз
- Дерекқорға тек серверлік функциялар арқылы қатынаймыз: `service_role` кілті тек Vercel environment variable-де. Барлық кестеде RLS қосулы, `anon` үшін бәрі жабық (қосымша қорғаныс)
- Vercel тегін жоспарында функция саны шектелуі мүмкін — ресми құжаттан тексер. Бір роутер-функция (`api/v1/[...path].js` немесе ұқсас) ішінде модульдер (`lib/routes/*.js`). `api/chat.js`, `api/content`, `api/telegram` орнында қалады
- Ортақ көмекшілер `lib/`-те: `db`, `auth`, `guard` (рөл тексеру), `rateLimit` (`api/chat.js`-тегі тәсілді ортаққа шығар), `audit`, `notify`, `escape`
- `GET /api/v1/config` — сайтта build қадамы жоқ болғандықтан, функция ажыратқыштары мен ашық кілттер браузерге осы арқылы жетеді
- **Ортақ ережелер (05–10 промпттар осыны сақтауы міндетті, README-ге «Ережелер» бөлімі етіп жаз):**
  - Шектеулер (орын саны, күніне N жазба, бір рет тіркелу, N шағымнан кейін жасыру) — тек Postgres деңгейінде: UNIQUE шектеулер және бір транзакциядағы Postgres функциялары (RPC). JS-те «оқы → тексер → жаз» жасама
  - Пайдаланушы жазған мәтін — сенімсіз дерек: сайтта тек `esc()` арқылы, серверде жасалатын беттерде (`/p/…`) серверлік экрандау арқылы, бот хабарламасында HTML экрандау арқылы шығады
  - Пайдаланушы берген сілтемелер тек `https://` (жұмыс беруші сайты, `source_url`, т.б.); `javascript:`, `data:` және басқалары қабылданбайды
  - Жоспарлы жұмыстың бәрі (еске салу, мерзімі біткенді жабу, 3-апталық сұрақтар) 03-промпттағы бір күнделікті Cron-диспетчер арқылы жүреді

## 2-КЕЗЕҢ — Telegram арқылы кіру
- Telegram ішінде: `initData` серверде HMAC арқылы тексеріледі, `auth_date` 24 сағаттан ескі болмасын. Кіргенде `Telegram.WebApp.requestWriteAccess()` сұралады — онсыз бот студентке жаза алмайды
- Telegram-нан тыс: Telegram Login Widget, `data-request-access="write"` атрибутымен, `hash` серверде тексеріледі
- `users.can_dm`: бот бұл студентке жаза ала ма. Жаза алмаса — хабарламалар сайттағы `notifs()` тізімінде көрінеді және «Ботқа /start жаз» деген шақыру шығады. 03-промпттағы «403 → белсенді емес» ережесі `can_dm = false`-ке айналсын
- Сессиялар: `sessions` кестесі (id, user_id, created_at, last_seen_at, expires_at, revoked_at, user_agent). Әр сұраныста сессия мен пайдаланушының `role` және `deleted_at` мәндері дерекқордан қайта оқылады — рөл алынса немесе аккаунт өшсе, бірден күшіне енеді
  - Студент: белсенді болса мерзімі өзі ұзарады (90 күн) — жүйеден өзінен-өзі шығармаймыз
  - admin, employer, university_staff: 14 күн
  - Профильде «Шығу» және «Барлық құрылғыдан шығу» батырмалары (іс-шарада ортақ ноутбуктан кіргендер үшін)
- Тасымал: қарапайым браузерде `httpOnly`, `Secure`, `SameSite=Lax` cookie. Telegram ішінде (әсіресе Telegram Web, ол Mini App-ты iframe-де ашады) cookie жетпеуі мүмкін — сондықтан Mini App-та сессия токені `Authorization` тақырыбымен жіберілсін (`initData`-дан алынған, тек жадта сақталады)
- Кіру міндетті емес. Аккаунт керек әрекетте ғана («Тіркелу», зат жариялау, ментор сұрау, өтінім жіберу) «Telegram арқылы кір» ұсынысы шығады
- `users`: id, telegram_id UNIQUE, username, name, lang, university, faculty, course, city, role, is_adult (bool), notif_prefs JSONB, can_dm, referred_by, consent_at, created_at, last_seen_at, deleted_at. Аккаунт ашылғанда 02-промпттағы `S.ref` мәні `referred_by`-ға жазылады
- Бот пен сайттағы аккаунт бір `telegram_id` арқылы байланады

## 3-КЕЗЕҢ — Келісім, жас және жеке деректер
- Аккаунт ашқанда бір экран: не сақталады, не үшін, кім көреді, қалай өшіріледі, қай деректер шетелдік сервистерге кетеді (AI-чат, аналитика, дерекқор орналасқан ел) + «Келісемін» → `consent_at`
- Сол экранда: «18 жасқа толдым» / «18-ге толмадым». `is_adult = false` студенттерге 07, 08, 10 промпттарда қосымша қорғаныс бар (тікелей контакт алмасу жоқ, кейбір вакансиялар көрінбейді)
- GPA мен телефон ешқашан міндетті емес және басқа адамдарға ешқашан көрсетілмейді
- `#/privacy` беті: құпиялылық саясатының ЖОБАСЫ, басында «Жоба — заңгер тексеруі керек» белгісі. Ішінде нақты тізім: қандай дерек, қай сервисте, қай елде сақталады
- Профильде «Деректерімді жүктеу» (JSON) және «Аккаунтты өшіру» (растаумен)
- Өшіру ережесі: студенттің жеке жазбалары (профиль, сессиялар, еске салулар, тіркелулер, өтінімдер, сұраныстар, маркет заттары мен фотолары, портфолио) шынымен өшеді. Басқа адамдар тәуелді контенттегі авторлық бағандар (`created_by`, `reviewed_by`, `verified_by`, `owner_user_id`) `ON DELETE SET NULL` — мысалы, амбассадор құрған іс-шара мен оған қатысқандардың расталған жазбалары сақталады, бірақ автордың аты жоғалады. `audit_log`-та тек анонимді жазба қалады
- Құрылғыдағы `S.profile` бұрынғыдай. «Аккаунтпен синхрондау» — студенттің таңдауымен

## 4-КЕЗЕҢ — Рөлдер мен ажыратқыштар
- Рөлдер: `student`, `ambassador`, `admin`, `university_staff`, `employer`. Рөлді тек admin береді, себебімен, `audit_log`-қа жазылады. Қосымша құқықтар (мысалы, бекітілген ментор, амбассадор-жетекші) рөл емес, сәйкес кестеден тексеріледі
- `CONFIG.features = { events, ambassador, mentors, market, portfolio, b2b }` — БӘРІ `true` (менің шешімім). Әрқайсысын Vercel environment variable арқылы өшіруге болсын (`FEATURE_MARKET=off`), `/api/v1/config` арқылы браузерге жетеді. Өшірілгенде батырма жасырылады, API 404 қайтарады
- `#/admin` — тек admin-ге: қолданушылар саны, рөл беру/алу, ажыратқыштардың қазіргі күйі, модерация кезегіне сілтеме (кезектің өзі 06-промптта)
- Бірінші admin `ADMIN_TELEGRAM_IDS` environment variable арқылы беріледі (03-промпттағы бот та осы айнымалыны қолданады)

## 5-КЕЗЕҢ — Ортақ хабарлама бюджеті (барлық функция осы арқылы ғана хабарлайды)
- `lib/notify.js` — ботқа хабарлама жіберудің ЖАЛҒЫЗ жолы. 03-промпттағы боттың «күніне 1» логикасын осы модульге көшір, екі бөлек санағыш қалмасын
- Хабарлама алдымен `notifications` кестесіне жазылады (сайттағы `notifs()` осыдан оқиды), сосын `can_dm` болса ботқа жіберіледі
- Екі түр:
  - `digest` (мерзім еске салуы, іс-шара еске салуы, 3-апталық сұрақтар, апталық дайджест) — студентке күніне ЕҢ КӨБІ 1 бот хабарламасы. Бірнешеуі түссе — біреуіне біріктіріледі, приоритет: дедлайн > іс-шара > қалғаны. Күнделікті Cron-диспетчер жібереді
  - `direct` (тікелей жауап: «ментор табылды», «жұмыс беруші шақырды», «постың жарияланды») — бірден жіберіледі, бірақ күніне ең көбі 3
- Санаттар: `deadlines`, `events`, `mentors`, `market`, `jobs`, `community`. Студент `#/settings`-те әр санатты өшіре алады (`users.notif_prefs`)
- Түнгі тыныштық: 22:00–08:00 (Asia/Almaty) — `direct` таңға ауысады
- Үні жылы әрі кінәсіз

## Аяқтау
Толық тексер: аккаунтсыз сайт бұрынғыдай; Telegram ішінде, Telegram Web-те және қарапайым браузерде кіру; бір студент басқа студенттің деректерін API арқылы оқи алмайды (әр эндпоинтке авторизация тесті); рөл алынғанда сол сәтте күшіне енеді; аккаунтты өшіргенде жеке деректер өшеді, ал басқалардың расталған жазбалары қалады; браузер кодында `service_role` жоқ; күніне 1 бот хабарламасы ережесі тестпен тексерілген. README жаңарт. Қорытындыла.
