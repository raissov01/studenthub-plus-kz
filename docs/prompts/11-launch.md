# TAPSYRMA 11: Student Hub — іске қосуға дайындау: толық тексеру, қауіпсіздік, интернетсіз жұмыс

Бұл — соңғы промпт. 01–10 орындалған, барлық функция ажыратқышы қосулы. Алдымен бүкіл жобаны басынан аяғына дейін зерттеп шық. Бұл кезеңде жаңа функция ҚОСПА — тек тексер, түзет, нығайт.

МАҢЫЗДЫ: кезең-кезеңмен жаса, әр кезеңнен кейін тоқтап, табылған мәселелер тізімін және не түзеткеніңді маған көрсет.

## 1-КЕЗЕҢ — Қауіпсіздік аудиті
- Барлық API эндпоинттерінің кестесін жаса: жол, әдіс, кім шақыра алады (аноним / student / ambassador / university_staff / employer / admin), rate limit бар ма, кіріс валидациясы бар ма
- Әр эндпоинтке авторизация тесті: рұқсаты жоқ рөл 401/403 алады; бір студент басқа студенттің, бір компания басқа компанияның, бір университет басқа университеттің деректерін ала алмайды
- XSS: дерекқордан келетін барлық мәтін `esc()` арқылы шығатынын тексер (студенттер мен жұмыс берушілер жазған мәтін — сенімсіз дерек)
- Құпиялар: браузерге жететін кодта `service_role`, `BOT_TOKEN`, API кілттері жоқ; git тарихында да жоқ
- Webhook (`secret_token`), Cron (`CRON_SECRET`), сессия cookie баптаулары тексерілген
- Қауіпсіздік тақырыптары (`vercel.json`): Referrer-Policy, Permissions-Policy (бүкіл бетке ортақ: геолокация картаға керек, қалғаны өшірулі), Content-Security-Policy. Қолданбада inline скрипт пен inline `style` көп, сонымен қатар telegram.org, аналитика, Supabase, Google Fonts керек — сондықтан CSP-ны алдымен `Content-Security-Policy-Report-Only` түрінде қосып, бұзушылықтарды жинап, сосын ғана қатаң режимге көшір

## 2-КЕЗЕҢ — Сценарийлік тесттер (Playwright)
Телефон енінде (390px және 360px), қазақша және орысша:
1. Жаңа студент: онбординг → мүмкіндік ашу → мерзімді сақтау → ботқа өту
2. Кіру: Telegram арқылы (тест режимінде қолдан жасалған initData) → профиль синхрондау → аккаунтты өшіру
3. Іс-шара: тіркелу → ұйымдастырушы QR ашады → студент сканерлейді → портфолиода «Расталған ✓»
4. Амбассадор: өтінім → admin бекітеді → мүмкіндік ұсынады → admin кезектен бекітеді → сайтта көрінеді
5. Ментор: сұраныс → ментор өтінімі → қолмен жұптау → 3-апталық сұрақ
6. Маркет: зат жариялау (фото EXIF-сіз) → шолу → «Берілді»
7. Жұмыс беруші: тексеру → вакансия → студент өтінімі → «Шақырылды» → студентке хабарлама
8. Университет: ресми мүмкіндік жариялау → жиынтық статистика (5-тен аз топ жасырын)
- Тесттер репозиторийде қалсын, README-де іске қосу командасы
- Тесттегі жасанды `initData` (кіруді айналып өтетін тест режимі) `VERCEL_ENV === 'production'` болғанда МҮЛДЕ жұмыс істемейтінін тексер — бұл кері есік болып қалмасын. Тесттер бөлек тест Supabase жобасына қосылады, нақты деректерге тимейді

## 3-КЕЗЕҢ — Хабарламалар мен деректердің тұтастығы
- Бір студентке бір күнде барлық функциядан келетін хабарлама санын тестпен есепте: `digest` ≤ 1, `direct` ≤ 3, түнгі тыныштық сақталады, өшірілген санат келмейді
- Аккаунтты өшіру: схемадан пайдаланушыға байланған БАРЛЫҚ кестенің тізімін өзің шығар (кемінде: users, reminders, event_regs, ambassador_terms, ambassador_applications, mentors, mentor_requests, mentor_pairs, market_items және фотолар, applications, portfolio_settings, submissions, employer_members, sessions, notifications) және әрқайсысында шынымен өшетінін тексер. Сонымен қатар: Storage-тегі фотолар, аналитикадағы пайдаланушы жазбасы (PostHog-та person өшіру), `client_errors`-та жеке дерек жоқ екені. Студент компания иесі болса — компанияны басқа мүшеге беру немесе тоқтату жолы болсын
- Дедлайны өткен мүмкіндіктер, мерзімі біткен вакансиялар мен маркет заттары автоматты жабылатынын тексер

## 4-КЕЗЕҢ — Интернетсіз ашылу (PWA)
- 02-промпттағы негізгі service worker-ді кеңейт: қолданба қабығы, сабақ кестесі, кампус картасы, электрондық билеттер мен студенттік QR интернетсіз де ашылсын. `/` кэштеледі (`/index.html` емес), `/api/*` пен `/p/*` ешқашан кэштелмейді
- Интернет жоқ кезде түсінікті белгі: «Интернет жоқ — соңғы сақталған деректер көрсетілді»
- Жаңа нұсқа шыққанда: «Жаңарту бар — жаңарту» батырмасы (бетті өзі күтпеген сәтте қайта жүктемейді)

## 5-КЕЗЕҢ — Демо деректерден нақтыға көшу
- `#/admin`-де «Демо деректерді көрсету» баптауы. Әр бөлімде (жұмыс, мүмкіндік, іс-шара, жеңілдік) нақты жазба 5-тен көп болса, сол бөлімнің демолары автоматты жасырылады
- Демо профиль («Құралай») тек «Үлгі профильмен қарау» таңдалғанда
- Барлық «үлгі» ескертулерін тексер: нақты деректе жоқ, демода бар

## 6-КЕЗЕҢ — Қателерді бақылау және күнделікті жұмыс
- Браузер қателері `client_errors` кестесіне жиналсын (хабар, экран, браузер; жеке дерексіз; rate limit)
- `#/admin`-де «Денсаулық» беті: соңғы 24 сағаттағы қателер, бот webhook күйі, соңғы Cron уақыты, модерация кезегінің ұзындығы
- README-ге «Апта сайын не істеймін» тізімі: модерация кезегі, ескі мүмкіндіктерді тексеру, амбассадорлармен байланыс, аналитикадағы 3 көрсеткіш
- Supabase деректерінің резервтік көшірмесін қалай алатыны (тегін деңгейдің мүмкіндігін тексеріп) README-де

## Аяқтау
Соңғы есеп: не тексерілді, не түзетілді, не әлі тәуекел болып қалды (адал тізім). Нұсқаны көтер (`Student Hub 2.0`), README-ге өзгерістер тізімі. Іске қосудан бұрын маған «өзің істейтін» қалған қадамдарды тізіп бер.
