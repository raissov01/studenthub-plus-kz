# Студент дауысы: сауалнама, анонимді өтініш, әл-ауқат

Үш функцияның әрқайсысының өз ажыратқышы бар, бәрі әдепкі бойынша **өшірулі**:

| Ажыратқыш | Не қосады | Код |
|---|---|---|
| `FEATURE_SURVEYS` | `/surveys` (студент), `/voice` → «Сауалнамалар» (қызметкер) | `backend/internal/surveys` |
| `FEATURE_FEEDBACK` | `/feedback` (студент), `/voice` → «Өтініштер», «Баптау» | `backend/internal/feedback` |
| `FEATURE_WELLBEING` | `/wellbeing`, `/voice` → «Баптау» → психолог байланыстары | `backend/internal/wellbeing` |

Ортақ көмекші пакет: `backend/internal/univoice`. Миграция: `backend/migrations/20261105000041_univoice.sql`.
Фронт: `frontend/src/components/views/voice.tsx`, `frontend/src/lib/voice.ts`.

«Қызметкер» деген: `admin` немесе admin бір университетке бекіткен `university_staff` (`university_staff`
кестесі, `docs/ACCOUNTS.md`). Бекітілмеген `university_staff` — 403. Басқа университеттің жазбасы 404 қайтарады
(жоқ жазбадан айырмашылығы жоқ).

## Қосу

1. Миграция: `cd backend && go run ./cmd/migrate`.
2. Env: `FEATURE_SURVEYS=true`, `FEATURE_FEEDBACK=true`, `FEATURE_WELLBEING=true` (керегін ғана), API-ді қайта іске қос.
   Қосымша: `FEEDBACK_PER_DAY` (бір аккаунтқа тәулігіне өтініш, әдепкі 5).
3. Admin `/admin/staff` арқылы қызметкерді университетке бекітеді (бұрыннан бар).
4. Өтініштер: admin `/voice` → «Баптау» → университет атауын жазып, «Әдепкі тізімді қосу» (Деканат, Ректорат,
   Жатақхана, Асхана, IT қызметі, Студенттер ісі), әр алушыға қызметкер id-лерін береді. Қызметкері жоқ алушы
   студентке көрінбейді.
5. SLA еске салу: хосттағы timer-ге сағат сайын `curl -H "Authorization: Bearer $CRON_SECRET" 127.0.0.1:8110/api/cron/feedback`
   (мысалы, бар `studenthub-notify` timer-інің скриптіне бір жол). Мерзімі өткен әр өтініш үшін бекітілген
   қызметкерлерге тәулігіне ең көбі бір хабарлама.
6. Әл-ауқат: қызметкер не admin `/voice` → «Баптау» → «Психолог байланыстары»-на тек **нақты, тексерілген**
   байланыстарды енгізеді. Бос болса, студент «әлі қосылмаған» дегенді көреді — ойдан байланыс ешқашан көрсетілмейді.

Студенттің университеті `users.university` бойынша дәл сәйкестікпен салыстырылады (бар b2b кодындағыдай). Сайттағы
профиль синхроны бұл өріске тілге қарай «Сейфуллин университеті» не «Университет им. С. Сейфуллина» жазады, ал
қызметкерді бекіткенде admin нақты бір жолды жазады — екеуі бірдей болуы керек. Бұл — бұрыннан бар шектеу.

## 1. Сауалнамалар

- Сұрақ түрлері: `single`, `multiple`, `scale` (1–5 не 1–10), `text` (≤500 таңба), `matrix` (жолдар × 1–5/1–10);
  әрқайсысында `required`. 1–40 сұрақ.
- Аудитория: факультет / курс / топ (`points_wallets.study_group`) тізімдері; бос тізім = университеттің бәрі.
  Тек `student`, `ambassador`, келісім берген.
- Ашылу/жабылу күндері; жарияланған сауалнаманың сұрақтары қатырылады (тек жабылу күнін өзгертуге болады).
- Үлгілер (`lib/voice.ts → templates`): «Оқытушыны бағалау», «Асхана сапасы», «Жатақхана» — тек сұрақтар, дерек жоқ.
- Ұпай: аяқтаған сауалнамаға бір рет `survey` себебі, 15 XP + 5 монета, тәулігіне 3-тен көп емес (`FEATURE_POINTS`).

### Анонимдік схемасы

```
server_key = HMAC-SHA256(SESSION_SECRET, "studenthub/survey-marker/v1")   — дерекқорда жоқ
K_s        = HMAC-SHA256(server_key, survey_id ‖ 0x00 ‖ surveys.marker_salt)  — salt: 32 кездейсоқ байт
marker     = HMAC-SHA256(K_s, user_id)                                     → survey_markers(survey_id, marker)
```

- `survey_responses`: `id uuid` (кездейсоқ), `survey_id`, `answers jsonb`, ірі сегмент `faculty`, `course`.
  **user бағаны жоқ, уақыт бағаны жоқ, users-ке FK жоқ** (тест: `TestAnonymousResponsesHaveNoUserLink`).
- `survey_markers` — тек «бұл адам жауап берді» белгісі, қайта дауыс бермеу үшін (PK `(survey_id, marker)`,
  параллель екі сұраныста да біреуі ғана өтеді). Маркер мен жауапты байланыстыратын баған жоқ.
- Дерекқор дампы жалғыз өзі қатысушылар тізімін бермейді: маркерді қайта есептеу үшін `SESSION_SECRET` керек.
- Ұпай журналында (`xp_events`) `ref_type='survey'`, `ref_id = hex(HMAC(SESSION_SECRET-тен туындаған басқа кілт,
  survey_id ‖ user_id))[:32]` — қай сауалнама екені аталмайды. Жауапта уақыт жоқ, сондықтан журнал жолының
  уақытымен жауапты байланыстыру мүмкін емес.
- Атаулы (анонимді емес) сауалнамада байланыс бөлек `survey_response_owners` кестесінде; студент оны экспорттан
  көреді, аккаунт өшсе жауабы да өшеді. Анонимді жауаптар ешкімдікі емес, экспортқа кірмейді, өшпейді.

Не көре алады:

| Кім | Не |
|---|---|
| Студент | ашық сауалнамалар, өзінің «жауап бердім» белгісі; жібергеннен кейін өзгерте алмайды |
| Қызметкер / admin | тек жиынтық нәтиже (төмендегі k-ережемен), CSV — тек жиынтық |
| Сервер иесі (`SESSION_SECRET` + дерекқор) | кімнің *қатысқанын* есептей алады, бірақ **кімнің не жауап бергенін — жоқ** |

Қалдық тәуекелдер (адал айтамыз): Postgres кестеде жолдарды физикалық түрде қосылу ретімен сақтайды, сондықтан
superuser деңгейіндегі қатынасы бар адам рет пен басқа логтарды салыстыруы теориялық түрде мүмкін; API логтарына
user id мен жауап бірге жазылмайды. Мәтіндік жауапта студент өзін өзі атап қоюы мүмкін.

### k-анонимдік (K = 5)

- Жалпы жауап саны 5-тен аз болса — тек сан, ешбір бөлу жоқ.
- Сұраққа жауап бергендер 5-тен аз болса — сол сұрақ жасырын.
- Бөлу (`?by=faculty|course`): 5-тен аз топ «басқалары»-на қосылады; «басқалары» 1–4 болып қалса, ең кіші көрінетін
  топтар да оған қосылады (комплементарлы жасыру: әйтпесе «барлығы − көрінетін топтар» кіші топты ашар еді). Топ
  біреу ғана қалса — бөлу жасырылады. Бір топта сұраққа 5-тен аз жауап болса, сол сұрақ барлық топта жасырылады.
  Мәтіндік жауаптар ешқашан бөлінбейді; жалпы көріністе кездейсоқ ретпен беріледі.
- CSV: `question_id, question, row, answer, count, answered, mean` — жеке жауап та, мәтін де жоқ.

## 2. Анонимді ұсыныс және шағым

- Алушылар университет бойынша (`feedback_recipients`), әрқайсысына қызметкерлер (`feedback_recipient_staff`) және
  SLA (сағат). Санаттар: ұсыныс, шағым, сұрақ, алғыс. Мәтін 10–3000 таңба, фото (міндетті емес).
- Фото: браузер canvas арқылы кішірейтеді, сервер `market.Process` арқылы JPEG-ке қайта кодтайды — EXIF (GPS), XMP,
  ICC, т.б. метадерек түгел өшеді (тест: `TestPhotoEXIFStripped`). Фотоны тек алушының қызметкері мен admin көреді.
- Күйлер: `new → in_progress → answered → closed`; студент жазса `answered → in_progress`, SLA қайта басталады.
  Жауап келгенде: атымен жіберген студентке — хабарлама (inbox + Telegram, `community` санаты); анонимге — құрылғы
  «Менің өтініштерім»-ді ашқанда «Жаңа жауап» белгісін көреді (сервер оны таба алмайды, сондықтан push жоқ).

### Анонимді өтініш қалай жұмыс істейді

1. Студент кіреді (тек университет студенттері жазуы үшін) және «Анонимді» режимді таңдайды.
2. Сервер өтінішті **author_id-сіз** сақтайды (`check (not anonymous or author_id is null)`), 32 кездейсоқ
   байттан токен жасайды, базаға тек `SHA-256(token)` жазады, токенді жауапта **бір рет** қайтарады.
3. Токен тек құрылғыда, `localStorage['studenthub.feedback.v1']`-де сақталады. Аккаунтқа жазылмайды — әйтпесе өтініш
   адаммен байланысып қалар еді. Студент кодты көшіріп алып, басқа құрылғыда «Кодпен ашу» арқылы қосуға болады.
4. Жауаптарды оқу/жазу: `POST /api/feedback/lookup {tokens}`, `/tickets/{id}/messages {token, body}`,
   `/tickets/{id}/read {token}` — сессия керек емес, токен өзі рұқсат. Тіпті жіберушінің өз сессиясы да токенсіз
   анонимді өтінішті аша алмайды (тест бар).
5. Анонимді өтініш пен оның хабарламаларының уақыты сағатқа дейін дөңгелектенеді.

| Кім | Анонимді өтініште не көреді |
|---|---|
| Алушының қызметкері | алушы, санат, мәтін, фото, күй, мерзім, хат алмасу. Жіберуші туралы **ештеңе** |
| Басқа қызметкер | ештеңе (404) |
| Admin | барлық алушылардың өтініштері (сол мазмұн), белгіленген (held) өтініштер модерация кезегінде — `submitted_by` бос |
| Дерекқор иесі | дәл сол; жіберушіні байланыстыратын баған жоқ |

Қалдық тәуекелдер: жазу шегі (`rate_limits`, `fb:t:<user>` және жалпы `w:u:<user>`) бір терезе бойы қысқа
уақытқа сақталады; қызметкерге «жаңа өтініш» хабарламасы бірден жіберіледі. Сондықтан серверге толық қатынасы бар
адам өте қысқа уақыт аралығында уақытты салыстыруы теориялық түрде мүмкін. Мәтіннің өзі жіберушіні ашып қоюы мүмкін
(студентке ескертеміз).

### Қорғаныс

- Шек: аккаунтқа тәулігіне 5 өтініш (`FEEDBACK_PER_DAY`) + жалпы `auth.Write` шегі.
- Сөздік эвристика (`feedback/flags.go` ≡ `lib/voice.ts detectFlag`):
  - **қауіп / төтенше жағдай** (зорлық, қару, өзіне зиян): студент жібермей тұрып экранда ескерту мен 112 нөмірін
    көреді және «Оқыдым» белгісін қояды (белгісіз сервер 409 `escalation_notice` қайтарады). Өтініш `held` күйінде
    алушыға бармайды, модерация кезегіне (`kind=feedback`) түседі және барлық admin-ге бірден хабарлама кетеді.
  - **дөрекі сөз**: `held`, admin мақұлдағанша алушыға жетпейді.
  - Admin мақұлдаса — `new`, қызметкерлерге хабарлама; қабылдамаса — `closed`, себебі студентке хабарлама ретінде.

## 3. Әл-ауқат

Тек ақпарат: диагноз жоқ, медициналық кеңес жоқ. «Маған қазір көмек керек» батырмасы шұғыл нөмірлерді бірінші
көрсетеді (112, 103, 102, 101), содан кейін 150 мен 111, содан кейін университет психологы. Өзіне көмек карталары
(тыныс, ұйқы, емтихан стресі) — қысқа, бейтарап, дереккөзімен. Көңіл-күй белгісі тек құрылғыда
(`localStorage['studenthub.mood.v1']`, 30 күн), серверге ештеңе жіберілмейді, аналитика жоқ, «Тарихты өшіру» бар.
