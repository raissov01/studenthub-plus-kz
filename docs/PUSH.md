# Браузер хабарламалары (Web Push)

Студент «Баптаулар → Хабарламалар → Браузер хабарламалары» қосқыштын басса, хабарламалар Telegram ботына
емес, осы құрылғыдағы браузерге (PWA) келеді. Әдепкі бойынша **өшік**: `FEATURE_WEBPUSH` және VAPID кілттері
қойылмаса, ешқандай маршрут, қосқыш не жіберу жоқ.

## Қосу

```bash
cd backend && go run ./cmd/vapid-keys mailto:admin@studywithraissov.com
# VAPID_PUBLIC_KEY=B…
# VAPID_PRIVATE_KEY=…      ← құпия, репозиторийге салма
# VAPID_SUBJECT=mailto:admin@studywithraissov.com
```

Осы үш жолды және `FEATURE_WEBPUSH=true` жолын API-дің env файлына (`/opt/studenthub/.env`, жергілікті —
`docker/local.env`) қос, `push_subscriptions` миграциясын қолдан (`go run ./cmd/migrate`, деплой өзі жасайды) және
api-ді қайта қос. Фронтендті қайта жинау керек емес: қосқыш `GET /api/config` → `webPush: {enabled, publicKey}`
бойынша шығады.

| Айнымалы | Мәні |
| --- | --- |
| `FEATURE_WEBPUSH` | `true` — қосу. Басқа мән не жоқ — өшік (маршруттар 404, белгісіз маршрут сияқты) |
| `VAPID_PUBLIC_KEY` | base64url, 65 байт P-256 нүктесі (браузерге `applicationServerKey`) |
| `VAPID_PRIVATE_KEY` | base64url, 32 байт. Ашық кілтке сай келмесе — push өшік қалады |
| `VAPID_SUBJECT` | `mailto:…` не `https://…` (push сервисі байланысатын мекенжай) |

Кілтті ауыстырсаң, барлық жазылым жарамсыз болады (push сервисі 403/410 береді, жол өшеді) — студенттер
қосқышты қайта басады.

## Маршруттар (`backend/internal/webpush/http.go`)

| Әдіс | Жол | Не істейді |
| --- | --- | --- |
| `POST` | `/api/me/push` | `PushSubscription.toJSON()` (`endpoint`, `keys.p256dh`, `keys.auth`) сақтайды. Endpoint тек `https://`, кілттер тексеріледі. Бір браузер басқа аккаунтқа кірсе, жазылым жаңа аккаунтқа көшеді. Аккаунтқа ең көбі 10 жазылым, ескісі өшеді |
| `DELETE` | `/api/me/push` | `{endpoint}` — осы браузердің жазылымын өшіреді (тек өз жолы, RLS) |
| `POST` | `/api/me/push/test` | Барлық жазылымға тексеру хабарламасы (`?lang=en` — ағылшынша). Бюджеттен тыс, 10 минутта 5 рет. Жазылым жоқ болса 409 |

Барлығы `auth.Write` (Origin + жиілік шегі) және кірген аккаунт. `docs/SECURITY.md` генерацияланады.

## Кесте

`push_subscriptions` (`backend/migrations/20261105000047_push_subscriptions.sql`): `user_id`, `endpoint`
(unique), `p256dh`, `auth`, `ua` («Chrome 131»), `created_at`, `last_ok`, `failures`. RLS: студент тек өз жолын
оқиды және өшіреді (деректер экспорты `pushSubscriptions`); жазуды сервер жасайды. Аккаунт өшсе — cascade.
`notify_outbox.channel` — хабарлама қай арнамен кетті: `push` не `telegram`.

## Жіберу ережесі (`backend/internal/notify`)

Push — `internal/notify` диспетчерінің жаңа арнасы, бот сияқты бір жолмен өтеді:

1. Хабарлама алдымен сайттағы inbox-қа жазылады (бұрынғыдай).
2. Санат өшік болса — ешқайда жіберілмейді. Тыныш уақыт (22:00–08:00, Астана) — кейінге қалдырылады. Күндік
   бюджет (күніне 3 тікелей + 1 дайджест) push пен ботқа **ортақ**.
3. Аккаунтта браузер жазылымы бар болса — **push бірінші**. Кемінде бір браузердің push сервисі қабылдаса (201),
   хабарлама жіберілді деп саналады, бот хабарламасы кетпейді.
4. Push ешбір браузерге жетпесе (жазылым 404/410, 4xx, 5xx, желі) және аккаунтқа бот байланысқан болса — сол
   сәтте **ботқа** жіберіледі (fallback). Бот жоқ болса — хабарлама сағаттан кейін қайталанады; бірде-бір арна
   қалмаса, өшіріледі (inbox-та қалады).
5. Жазылымы жоқ, бірақ боты бар аккаунт — бұрынғыдай тек бот. Екеуі де жоқ — тек inbox.

Push-ты қайталау қауіпсіз: хабарламаның `tag`-ы `notify-<outbox id>`, құрылғы ескі көшірмені ауыстырады.
Push сервисі 404/410 берсе — жазылым бірден өшеді; 5 рет қатарынан қате берсе — да өшеді; 2xx `last_ok`-ты
жаңартып, қате санауышын нөлдейді.

Хабарлама: `{"title":"Student Hub","body":"…","url":"/event/12","icon":"/icons/icon-192.png","tag":"notify-42"}`,
шифрланған (RFC 8291 aes128gcm), VAPID қолтаңбасымен (RFC 8292), `TTL: 86400`, `Urgency: normal`. `url` —
inbox жолының сілтемесі, болмаса `/notifications`. Код тек стандарт кітапхана: `crypto/ecdh`, `crypto/hkdf`,
`crypto/ecdsa`; тест RFC 8291 A қосымшасындағы мысалды байтпен-байт қайталайды.

## Фронтенд

- `frontend/src/lib/push.ts` — қолдау (`pushSupport`), рұқсат, жазылу/өшіру, тексеру.
- `frontend/src/components/views/push.tsx` — қосқыш. Рұқсат **тек қосқышты басқанда** сұралады, бет ашылғанда
  ешқашан. Браузер рұқсат бермесе — түсініктеме.
- iPhone/iPad: Web Push тек басты экранға орнатылған қолданбада (iOS 16.4+). Safari-де ашылса, қосқыш өшік,
  астында «Бөлісу → Басты экранға қосу» нұсқауы.
- `frontend/public/sw.js`: `push` — хабарламаны көрсетеді (әр push міндетті түрде көрінеді, әйтпесе Safari
  жазылымды алып тастайды); `notificationclick` — ашық Student Hub терезесін сол бетке бұрады не жаңасын ашады
  (тек өз сайттың жолы); `pushsubscriptionchange` — жаңа жазылымды серверге жібереді.

## Тексеру

```bash
cd backend && go test ./internal/webpush/ ./internal/notify/ -run 'Push|RFC|VAPID|Subscribe|Send'
cd frontend && npx playwright test e2e/push.spec.ts
```

Қолмен: кілттер мен флагты қойып, `/settings` → қосқыш → «Тексеру хабарламасын жіберу».
